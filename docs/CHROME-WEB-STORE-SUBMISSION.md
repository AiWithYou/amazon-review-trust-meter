## ダッシュボードでの入力順

1. [Chromeウェブストア開発者ダッシュボード](https://chrome.google.com/webstore/devconsole)で既存アイテムを開き、「パッケージ」から新しいパッケージをアップロードします。まだアイテムがない場合は「新しいアイテム」を作成して同じZIPをアップロードします。
2. 認識されたバージョンが `2.2.1` であることを確認します。通常の提出はZIPで行います。既存アイテムでVerified CRX Uploadsを有効にしている場合は、登録済み秘密鍵による署名が別途必要です。
3. 「ストアの掲載情報」に概要、詳しい説明、カテゴリ「ショッピング」、言語「日本語」、サポートURLを入力し、上記のアイコン・スクリーンショット2枚・小さいプロモーション画像を登録します。説明の貼り付けには `.txt` を使います。
4. 「プライバシーへの取り組み」に単一目的、サイトアクセスの理由、リモートコード「なし」を入力します。ローカル処理でも申告が必要なため、掲載情報の正本どおり、公開レビュアー識別子、対応ページURL・ASIN、ウェブサイトのコンテンツの扱いを申告します。
5. プライバシーポリシーURLに `https://github.com/AiWithYou/amazon-review-trust-meter/blob/main/PRIVACY.md` を設定し、Limited Useの各宣誓を確認します。
6. 「テスト手順」に正本の審査担当者向け手順を貼り付けます。ログイン、テストアカウント、課金は不要です。
7. 「配布」で公開範囲と対象地域を選びます。Amazon.co.jp専用・日本語UIのため、日本が初回対象の候補です。
8. 全項目を保存してプレビューを確認し、公開準備ができた時点で審査へ提出します。審査通過後の公開時期を管理したい場合は、自動公開を外して延期公開を選びます。

公開範囲、既存アイテムの有無、署名設定、アカウントの登録・2段階認証状態はダッシュボードで確認してください。本準備ではこれらのアカウント設定を変更していません。

## 画像と動作確認

スクリーンショットは、実際のv2.2.1拡張コードとCSSが描画したサンプル商品の画面を撮影したものです。画像内に「サンプルデータ」と明記しています。実商品の検出性能や検出率を示すものではありません。

再撮影する場合は `npm run preview` を起動し、幅1280・高さ800で次を開きます。

- 一致例: `http://127.0.0.1:8766/store/dp/B012345678`
- 矛盾例: `http://127.0.0.1:8766/store/dp/B012345678?conflicts` を開き「詳細を見る」を押す

説明の一致例では、表記差 `12` と `12.0`、`5000` と `5,000` が矛盾になりません。矛盾例では、連続時間と容量の違いが具体的な根拠として表示されます。

## 確認した公式資料

- [画像要件](https://developer.chrome.com/docs/webstore/images): 128pxアイコン、440 × 280の小さいプロモーション画像、1280 × 800または640 × 400のスクリーンショット1枚以上。
- [更新手順](https://developer.chrome.com/docs/webstore/update?hl=en): バージョンを増やしたZIPをアップロードし、掲載情報を更新して再審査へ提出。
- [初回公開と延期公開](https://developer.chrome.com/docs/webstore/publish): 掲載・プライバシー・配布・テスト手順を入力し、審査後の公開タイミングを選択。
- [データポリシーFAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq): 外部送信がなくローカルでのみ処理する情報も、データ取り扱いの開示とプライバシーポリシーの対象。
