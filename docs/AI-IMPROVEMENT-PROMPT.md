# AI改善指示プロンプト（v2.0.4 アルゴリズム改善）

以下をAIにそのまま貼り付けて使用する。

---

あなたはAmazonレビュー分析拡張機能（amazon-review-trust-meter v2.0.4）の改善を行う。
対象: `scoring-base.js` / `scoring-features.js` / `scoring.js` / `docs/ALGORITHM.md` / `tests/scoring.test.cjs`

## 厳守する制約

- 設計思想を維持する: 誤警告（正常商品の要注意扱い）の最小化を検出率より優先。単独特徴で強い判定を出さない。
- 完全ローカル・追加権限なし・外部送信なしを維持する。
- `analyzeProduct` の戻り値の形（公開プロパティ名）を変えない。
- 既存テストを全て通し、変更ごとに回帰テストを追加する。
- `docs/ALGORITHM.md` を実装と同時に更新し、バージョンを上げる。
- 断定表現を使わないUI方針（「兆候」「確認推奨」等）を維持する。

## 改善タスク（優先度順）

### 1. 計算済みだが未使用の `ratingShift` を裏付けに使う
`scoring-features.js` の `findTemporalBurst` は `ratingShift`（バースト内外の平均星差）を返すが、`scoring.js` はどこでも使っていない。`temporalSupport.corroborated` の判定に「`ratingShift >= 0.8` かつバースト方向が高評価/低評価に揃う」を裏付け条件の一つとして追加する。単独では加点しないこと。

### 2. 未使用の `reviewerId` でページ内重複投稿者を検出する
入力に `reviewerId` があるのに一切使われていない。表示レビュー内で同一 `reviewerId` が2件以上あり、かつ評価方向が揃う場合、`provenance` 群に中程度のシグナル（8〜10点）を追加する。空文字・未取得は除外する。低コストで適合率が高い特徴なので最優先で入れる。

### 3. バースト検出の一様分布仮定を修正する
`findTemporalBurst` の `expectedRatio = windowDays / spanDays` は投稿が期間中一様である仮定だが、実際のレビューは発売直後に前方集中する。正常な新発売商品を過剰検出する（Vine補正だけでは不十分）。対策:
- バースト区間が観測期間の先頭（最古レビュー付近）に接する場合は strength を減衰させる（発売直後集中の可能性）。
- 3窓×全位置の最大値走査は多重検定でz値が膨らむ（scan statistic）。z閾値を引き上げるか走査補正を入れる。
テスト: 「発売直後30日に高評価が自然集中し、その後まばら」なフィクスチャで加点されないこと。

### 4. 短文2-gramクラスタの誤検知を抑える
`getSimilarityThreshold` は本文30〜42文字帯で2-gram＋閾値0.39になるが、日本語の短い定型的レビューは独立していても文字2-gramの重複が大きく、偽クラスタを作りやすい。さらに `analyzeIndividualReviews` ではクラスタ所属（+0.38）と汎用度（+0.14）が同一原因で二重加算される。対策:
- `genericness >= 0.68` の本文はクラスタ対象（eligible）から除外するか、クラスタ所属時に汎用度加点を打ち消す。
- 2-gram帯（<42文字）の閾値を引き上げる。
テスト: 独立した短文高評価5件（「使いやすくて満足。配送も早い」系の言い換え）がクラスタを形成しないこと。

### 5. 小標本の比率判定をWilson下限に置き換える
`positiveUnverifiedRatio >= 0.65`（n=6なら4/6で成立）等、生比率の閾値判定が多数あり小標本で不安定。`unverified*Ratio` / `genericRatio` / `burstDuplicateRatio` / `directionRatio` を Wilson score 下限（95%）で評価するヘルパーを `scoring-base.js` に追加して置き換える。誤警告最小化の設計目標に合致する。

### 6. 崖状の閾値を平滑化する
`genericness >= 0.68`、`five >= 0.92`、`strength >= 0.35` 等のハード閾値が多く、レビュー1件の増減でラベルが飛びやすい。高得点シグナル（10点以上）から順に、閾値±10%程度の smoothstep 傾斜に置き換える。回帰テスト: 任意のフィクスチャでレビュー1件を除去したとき総合スコアの変動が±12点以内であること。

### 7. `rating_mismatch` を弱める
Amazonの表示平均は単純なヒストグラム平均ではなく重み付け（機械学習）平均のため、乖離0.24は正常商品でも発生する。閾値を0.35程度へ引き上げるか、`countReliability` が高い場合のみシグナル化し、それ以外は observation に降格する。

### 8. `addSignal` の最低1点保証を廃止する
`Math.max(1, Math.round(rawPoints * reliability))` により reliability がほぼ0でも各シグナルが1点入る。丸め後0点のシグナルは配列に追加しない（表示もしない）よう変更する。

### 9. 類似度閾値の単調性を直す
`getSimilarityThreshold` が 0.62 → 0.39 → 0.40 → 0.38 と非単調。長さに対し単調非増加になるよう整理し、意図があるならコメントで根拠を明記する。

### 10. `helpfulVotes` を弱い減衰材料として使う
参考票の多いレビューはコミュニティ検証済みの可能性が高い。`analyzeIndividualReviews` で `log10(1+votes)` に比例した小さなリスク減算（最大-0.06程度）を入れる。票の操作もあり得るため効果は必ず上限で抑え、加点方向には使わない。

## 進め方

1. タスクごとに独立して実装し、`node tests/scoring.test.cjs` で全テスト通過を確認してから次へ進む。
2. 各タスクで最低2件（陽性1・陰性1）のテストケースを追加する。
3. 全タスク完了後、`docs/ALGORITHM.md` の該当節を更新し、変更点の一覧を報告する。
4. 係数の根拠が説明できない変更はしない。迷ったら誤警告が減る側に倒す。

## 対象外（今回はやらない）

- 商品横断のレビュアーグラフ（外部送信が必要になるため。ALGORITHM.md §12 の通り別機能として設計）
- 「新着順」レビューの追加取得（取得ポリシー変更を伴うため要別途判断）
- 機械学習モデルの導入（検証データ整備が先。§13 の校正方針に従う）
