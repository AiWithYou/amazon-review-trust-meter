# v2.2.0 監査・改善記録

確認日: 2026-09-21。対象: ローカル判定エンジン、Amazon DOM抽出、再描画、Manifest V3、配布ZIP。

## 収集した知識と適用判断

| 一次資料 | 確認した内容 | 適用 |
|---|---|---|
| [Amazon KDP カスタマーレビュー](https://kdp.amazon.co.jp/ja_JP/help/topic/G202101910) | 星評価は単純平均ではなく機械学習モデルによる計算 | 件数が多くても単純平均との差だけで加点しない。差の観測表示は残す |
| [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) | DOMへのアクセスとisolated world、利用できる拡張APIの範囲 | 既存の宣言的content scriptと権限範囲を維持。追加通信・AI APIは導入しない |
| [MDN MutationObserver.observe](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver/observe) | childList、characterData、attributesは別々の監視対象 | 文字だけ・属性だけの更新も監視。対象外の変化は再解析しない |

レビュー不正の正解ラベル付き評価セットは未整備です。学習モデル導入や係数の全面調整は、誤検知率を比較できないため採用しませんでした。今回は再現できた不具合、根拠と一致しない加点、結果同一の高速化を優先しました。

## 修正した問題

- `Number(null)`により未取得割合が0%、未取得の星が低評価方向になる。未取得と実際の0を区別し、星は1〜5に限定。
- ヒストグラムの進捗属性がないのに0%として採用される。欠損を保持し、hrefから星を特定する行にも対応。
- 同じレビューIDがDOMに複製されると、本文・投稿者・投稿日集中の標本数が増える。DOM抽出と判定入口の両方でID重複を除外。IDのない別レビューは消さない。
- 11人・21人の参考票が1人になる。日本語「一人」と数値抽出を分離。
- 2月30日などの日付が時系列判定に混入する。日本語日付の実在性を検証。
- 説明文の長さだけで更新を判定し、同じ文字数の仕様変更やレビュータイトル変更を見落とす。入力内容を比較。
- childListだけの監視で文字・属性の変化を見落とす。対象属性を限定して監視。
- ページ全域の更新で再解析し、連続更新時に650msデバウンスが先延ばしになる。関連要素に限定し、200ms単位でまとめる。ブラウザによるタイマー抑制は別途あり。
- 自分の描画を監視し続けるループを防ぎつつ、親要素交換・カード単独削除から復帰。
- 星分布が揃うだけで本文1件でも「目立つ異常は少ない」となる。分析可能本文6件未満は「判定材料不足」。有効な星6件未満は補正評価を出さない。
- 充電時間と連続再生時間の誤比較、`5,000mAh`と`5000mAh`の誤比較。連続時間の文脈を限定し、桁区切りを正しく読む。曖昧な時間表記を見逃す側の変更。
- 配布ZIPにREADMEが参照する判定仕様が入っていなかった。仕様、監査記録、プライバシー文書を同梱。

## 性能測定

Windows / Node v24.14.0。`npm run benchmark`はGitタグv2.1.0と現在の本文クラスタ処理を同じV8環境で比較します。30回ウォームアップ後、30回ずつ9バッチを測定し中央値を使用。各条件で返却オブジェクト全体の一致を確認します。

| 合成入力 | v2.1.0 | v2.2.0 | 倍率 |
|---|---:|---:|---:|
| 短文20件 | 3.277 ms | 0.559 ms | 5.86倍 |
| 長文20件 | 45.016 ms | 6.389 ms | 7.05倍 |
| 24件 | 14.442 ms | 1.901 ms | 7.60倍 |

正規化済み本文と2/3-gram集合を比較ペア間で再利用します。類似度式・閾値は同じです。これは本文クラスタ処理単体の合成ベンチマークで、商品ページ全体の速度や実商品の識別精度を示しません。

## 検証と残る境界

- 既存31件にDOM・欠損・再描画などの回帰テスト14件を追加。`npm run check`の45件すべて合格。
- jsdomで実際のDOMとMutationObserverを使用。タイマーだけ決定的なテスト用キューに置換。
- 無関係なDOM変更100件で再判定予約0件、連続する関連変更20回で予約を先延ばししないことを確認。
- Chromeのローカル模擬商品ページで表示・詳細開閉・同文字数の仕様変更を確認。詳細を開いた状態を維持して注意度0→18へ更新。
- 通常幅と狭い画面を目視。狭い画面の実測viewport 450pxで、開閉両方のカードscrollWidthとclientWidthが一致。
- Chromeのログに検証対象由来のerror/warnなし。別のインストール済み拡張からの警告は対象外。
- `npm run package`と`npm run package:verify`で両ZIP内の各12ファイルの内容、版番号2.2.0、SHA-256を確認済み。
- chrome://extensionsへの操作はブラウザツールのURLポリシーにより拒否されたため、インストール済み拡張の読み込み元・再読み込み・Amazon実ページでの更新後動作は未確認。別経路で制限を迂回しない。ユーザーによる再読み込みが必要。
- ローカルプレビューは拡張と同じJS/CSSを通常のページスクリプトとして使うため、isolated world内の実拡張検証とは区別する。
- 監査時点ではGitHub Release公開・Chromeウェブストア更新は未実施。その後、リリース準備としてストア提出用ZIPと既存128pxアイコンのManifest指定を追加。ストア審査・公開はGitHub Releaseとは別工程。
